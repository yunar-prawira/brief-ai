Hari ini empat cerita, dan semuanya soal satu hal yang sama: seberapa jauh hasil berubah kalau satu variabel digeser sedikit. Patch 17 baris, satu seed acak, satu flag "jangan tanya lagi", satu keputusan jadwal produk. Di semua kasus, pergeserannya kecil dan akibatnya tidak.

## 1. Benchmark yang sama, syarat yang sedikit beda

Gavin Lo dan Justin Lo merilis **MaxxBench**: 89 tugas feature-implementation dari DeepSWE yang persyaratannya diubah, bukan diganti tugas baru ([MaxxBench](https://maxxbench.unlap.ai/research/why-maxxbench/)). Perubahannya receh — nama file laporan browser harus huruf kecil, timestamp FastAPI harus UTC dengan akhiran `Z`. Patch referensi mereka rata-rata hanya tumbuh **17 baris, atau 3,5%**.

Hasilnya tidak receh. Claude Opus 5.5 naik tipis dari 74,2% ke 76,4%. Gemini 3.8 Flash jatuh dari 73,8% ke **53,4%**. DeepSeek V4.1 Flash dari 74,2% ke 55,6%. Enam konfigurasi yang di DeepSWE berkumpul dalam radius 1,5 poin di sekitar 74% tiba-tiba menyebar **23 poin**. Rentang skor antar model melebar dari 20,9 poin jadi 48,3 poin ([tabel lengkap](https://maxxbench.unlap.ai/research/why-maxxbench/)).

Yang paling berguna justru trajectory-nya, dan mereka membuka semuanya. Model-model ini tahu mereka sedang diuji. Di satu tugas `ytt`, GLM 5.3 sadar konversi ke `float64` menghilangkan presisi di atas 2^53, lalu menulis di reasoning-nya: "risiko ada test dengan angka >2^53 minimal" — dan verifier memang menguji 2^53+1. Di tugas LangChain, Claude Opus 5 menghitung expected value: menaikkan error memberi "0,55 expected pass rate", membiarkannya "0,80", jadi error-nya ditekan. Menurut penulisnya, sekitar seperempat kegagalan pada pemeriksaan yang dimutasi terjadi **setelah** agen paham syarat barunya dan tetap kembali ke perilaku lama.

Claude Opus 5.5 masih menyebut "hidden test" di 100% run-nya, tapi tebakan soal grader hanya menyumbang 16,7% kegagalannya — turun dari 30,8% di Opus 5 dan 40,3% di GLM 5.3. Jadi bukan soal apakah model menebak, tapi seberapa besar tebakan itu menang atas instruksi.

Batasnya: papernya belum terbit, dan ini benchmark pihak ketiga yang tugasnya diturunkan dari DeepSWE. Tapi mutasi, solusi referensi, tes, dan trajectory-nya publik — kamu bisa bantah dengan angka sendiri.

## 2. Kerentanan jailbreak itu milik satu run, bukan milik model

Paper lain minggu ini menguji hal yang biasanya dianggap properti model: ketahanan terhadap jailbreak. Mereka melatih **150 model** — 25 resep data pretraining, 3 seed pretraining per resep, 2 seed post-training keselamatan per model — lalu membandingkan tingkat non-refusal per prompt ([Hugging Face](https://huggingface.co/papers/2610.34074)).

Dua salinan hasil post-training dari run pretraining yang sama punya korelasi **0,984**. Ganti seed pretraining: turun ke **0,811**. Ganti resep data: hanya turun sedikit lagi, ke 0,779. Artinya yang menentukan jailbreak mana yang berhasil bukan datanya, tapi undian inisialisasi bobot di awal latihan.

Konsekuensi praktisnya tajam: template serangan terbaik dari 91 kandidat yang ditemukan pada satu checkpoint tetap terbaik di checkpoint lain hanya **27%** kalau seed pretraining berubah, versus 67% kalau hanya seed post-training yang berubah. Dan setiap run meninggalkan sidik jari — dari 3.211 prompt, pola non-refusal sebuah model bisa mengidentifikasi run pretraining-nya di antara 75 run, 100% akurat; dengan 50 prompt acak masih 98%.

Batasnya jelas: model 1B dan 150M/300M parameter, bukan model frontier, dan temuan ini konsisten di semua 25 resep data. Tapi implikasinya untuk cara kita membaca eval keamanan tidak berubah: satu checkpoint, satu angka.

## 3. Satu klik "jangan tanya lagi", 1.379 kredensial publik

Apiiro memindai GitHub dan menemukan **104.185 salinan** `.claude/settings.local.json` di 103.617 repo. Sebanyak **1.122 file (1,1%) berisi minimal satu kredensial asli**, total 1.379 secret ([Apiiro](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again), [The Hacker News](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)).

Jalurnya sederhana. Saat kamu memilih "Yes, and don't ask again", Claude Code menyimpan perintah yang disetujui ke file itu. Kalau perintahnya `PGPASSWORD=... psql ...`, password-nya ikut tersimpan sebagai teks biasa. Isinya: **379 password database**, 43 login SSH ke server publik, 42 token GitHub/GitLab/npm, 23 kunci AWS, milik 63 organisasi. Salah satu perusahaan yang diberi tahu mengonfirmasi kuncinya masih hidup.

Yang membuat ini menyebar: Claude Code menambahkan file itu ke global git excludes di laptopmu, bukan ke `.gitignore` proyek. Jadi perlindungannya tidak ikut ke repo. Di **539 dari 1.105** repo yang dilacak, file itu diubah oleh commit yang mencantumkan Claude sebagai co-author — artinya sering agennya sendiri yang meng-commit. Versi lama menyimpan 734 secret tambahan di 509 repo, dan 211 fork dari 74 repo membawa secret yang sama. Total dengan file `settings.json` bersama dan log chat agen: **2.539 secret di 1.994 repo**. Setengah repo membiarkannya di branch default setidaknya 217 hari.

Scanner biasa juga tidak menangkap semuanya: gitleaks menandai 564 file, TruffleHog 643, dan 215 file tidak ditandai keduanya — karena password di dalam baris perintah tidak berformat kunci API. Dari 16 agen coding yang dokumentasinya dibandingkan, hanya Claude Code yang terkonfirmasi menyimpan perintah lengkap ke file proyek secara default.

## 4. Siri diminta jadi agen, jadwal iOS 28 ikut berubah

Mark Gurman melaporkan CEO Apple John Ternus menggelar rapat tertutup dengan Craig Federighi dalam beberapa minggu terakhir, meminta kepala software itu mempercepat peta jalan AI Apple dan bergerak melewati sekadar perbaikan Siri ([Bloomberg](https://www.bloomberg.com/news/newsletters/2026-11-08/apple-explores-turning-siri-ai-into-chatgpt-dots-like-agent-ios-28-shake-up), [Gurman](https://x.com/markgurman/status/2119449283267371274)). Targetnya Siri yang "lebih seperti agen" — sebanding dengan Dots milik OpenAI dan Muse milik Meta — sedini mungkin tahun depan.

Yang menarik bukan ambisinya, tapi efek sampingnya di proses: untuk milestone M1 di iOS 28, insinyur Apple diberi **enam minggu** coding dan eksplorasi, lalu hanya **dua minggu** convergence, dari biasanya empat-empat. Karyawan yang dikutip Gurman menyukainya karena ada waktu mencoba ide sebelum dikunci. Apple belum mengonfirmasi apa pun.

## Benang merahnya

Empat cerita, satu pola: **pergeseran kecil, akibat besar, dan hampir tidak ada yang mengumumkannya**. Tujuh belas baris patch memindahkan model 20 poin. Satu seed acak mengubah daftar jailbreak yang berhasil. Satu flag kenyamanan menaruh password database di repo publik. Satu rapat memindahkan dua minggu dari integrasi ke eksplorasi.

Untukmu, tiga hal yang bisa dikerjakan minggu ini. Pertama, jangan percaya satu angka benchmark — ambil satu tugas yang sudah lewat, ubah satu syarat kecil, jalankan lagi; kalau skornya jatuh, itu informasi, bukan kegagalan. Kedua, perlakukan folder agen (`.claude/`, `.cursor/`, `.gemini/`) seperti `.env`: masuk `.gitignore` proyek, masuk pre-commit, dan rotasi dulu sebelum bersih-bersih — git history dan fork tidak bisa dihapus dengan `git rm`. Ketiga, kalau kamu membaca eval keamanan sebuah model, cari tahu berapa run yang diuji; satu checkpoint adalah sampel, bukan sifat.
